一、使用方式与组成

SamuraiCombatant 是角色组合入口（门面），挂在角色根对象上，继续保存 Animator、CharacterController、Profile、BladeBase、BladeTip 和阵营引用。它在初始化时创建普通 C# 服务、连接事件，并保留既有输入、AI、HUD使用的公开接口。

普通 C# 服务不是 MonoBehaviour，不需要也不能逐个拖到 GameObject：
- SamuraiActionController：动作状态、连段、蓄力、取消窗口、闪避输入缓存和动作时钟。
- SamuraiDodgeFollowUp：由ActionController持有的普通C#辅助服务，只管理闪避追击输入缓存与结束宽限，不播放动画、不做伤害查询，也不额外推进Tick。
- SamuraiCharacterMotor：CharacterController移动、重力、转向、动作步进与复位。
- SamuraiKnockback：按独立命中后退参数积分快速起步、逐渐减速的水平位移，通过Motor碰撞；由角色Tick推进，命中停顿时冻结。
- SamuraiAnimationDriver：Animator状态播放/查询、八方向片段选择、方向迟滞和步态相位衔接。
- SamuraiVitals：生命、耐力、消耗与恢复延迟；实现只读ISamuraiVitalsView。
- SamuraiDefense：F按下边沿、持防、完美格挡窗口、消费与冷却；不直接扣血或播放动画。
- SamuraiDamageResolver：普通受击、闪避、格挡、完美格挡、破防和死亡规则；通过ISamuraiCombatReactions请求反应。
- SamuraiWeaponAttack：攻击有效窗口、轨迹采样、阵营过滤、单招去重、遮挡和向受击对象提交伤害。
- WeaponTrailDetector：只做胶囊重叠、刀身虚拟点SphereCast及遮挡查询，返回按接触时间排序的几何结果；不知道生命、动作、阵营或SamuraiCombatant。
- SamuraiEnemySensors：敌人的视线、移动路径和落脚面检查。
- SamuraiBehaviorTree中的节点：通用ConditionNode、ActionNode、Sequence和Selector，不依赖Unity或角色类型。
- SamuraiPlayerPresentation：独立玩家所需默认相机/HUD的创建与清理，由玩家输入组件管理生命周期。

需要挂在场景对象上的组件：
- SamuraiCombatant，以及Animator、CharacterController等场景组件。
- 玩家使用SamuraiPlayerInput；训练对手使用SamuraiTrainingEnemy。每个角色只能有一个Tick输入驱动。
- SamuraiTargetLock负责选择和保持锁定目标。
- SamuraiOrbitCamera、SamuraiCombatHUD负责镜头和UI。
- WeaponTrailGizmos是可选观察组件，挂在角色根对象上，独立开关；仅Scene视图记录/绘制，不参与命中结算。

SamuraiCombatProfile和SamuraiActionDefinition仍为ScriptableObject配置资产。运行服务共享配置引用，各角色的当前生命、耐力、窗口、缓存与命中集合分别保存在服务实例内。原角色Prefab的SamuraiCombatant字段和脚本GUID继续沿用。

二、调用方向与时序

输入或AI
  → SamuraiInputFrame
  → SamuraiCombatant.Tick
  → SamuraiActionController
  → 动作许可/连段时序，以及移动、动画、耐力、防御服务

Unity完成Animator骨骼求值
  → SamuraiCombatant.LateUpdate
  → EvaluateWeaponContacts
  → SamuraiWeaponAttack.Sample
  → WeaponTrailDetector.Query / Obstructed
  → ISamuraiDamageReceiver.ReceiveHit
  → 对手的SamuraiDamageResolver
  → 对手生命/耐力及ISamuraiCombatReactions

动作切换会取消旧轨迹；新攻击开始才建立新一招采样。命中回调若触发弹反、状态打断或切换招式，攻击编号和轨迹版本检查会终止旧查询的后续结算，不将旧刀位写回新动作。

普通运行只由LateUpdate采样一次。手动模拟或验证时，可在Tick、Animator.Update和Physics.SyncTransforms之后调用EvaluateWeaponContacts；不要再在正常Update额外调用它。

三、对外接口

Runtime/SamuraiCombatContracts.cs集中定义输入帧、状态/命中结果、伤害数据及接口。

actor.Vitals：ISamuraiVitalsView，只读生命/耐力和Changed事件。
actor.Actions：ISamuraiActionView，只读状态/当前动作/攻击编号，并提供TryStartAttack合法动作请求；IsSprinting与SprintElapsedSeconds观察实际奔跑资格。
actor.IsBeingKnockedBack：观察后退服务是否仍有剩余时段；不直接改位移或伤害。
actor.Movement / actor.Animation：较低层的移动和动画服务入口；正常战斗统一由动作协调器使用，扩展时避免多个模块同时驱动同一胶囊或Animator。
actor.Weapon：武器攻击适配服务，可观察SweepQueried、ContactResolved和HistoryCleared事件。

角色事件：
- StateChanged(string)：动作状态变化，可驱动准备、挥砍、受击等表现；事件发生时按状态名判断，不假设动作配置已完成后续赋值。
- HitReceived(SamuraiHitResult)：自身受击结算结果。
- GuardContacted(SamuraiGuardContact)：普通或完美格挡结算后、HitReceived之前触发；保留物理Point、可选ClashPoint、结果、来源和实际回耐，供金属碰撞表现使用。
- DeflectPerformed(float, Vector3, ISamuraiDamageReceiver)：新弹反成功后的实际回耐、世界物理接触点及攻击来源；在HitReceived之前触发，保留既有订阅兼容。金属碰撞组件只订阅GuardContacted，避免双播。
- HitDealt(SamuraiCombatant, SamuraiHitResult)：兼容原角色对角色通知。
- DamageDealt(ISamuraiDamageReceiver, SamuraiHitResult, Vector3)：通用目标及世界命中点，适合新命中特效、音效或战斗日志。
- Died()：死亡通知。

订阅者应成对订阅/取消订阅。Configure会重建服务并重置角色；若直接订阅某个服务实例，在重新Configure之后需重新取得引用。通常表现功能优先订阅SamuraiCombatant上的稳定事件。

四、新增技能或攻击

同类型近战技能通常只需：
1. 创建SamuraiActionDefinition资产，填写对应Animator状态名、片段、伤害、耐力、命中窗口、位移和取消窗口。
2. 在角色Animator Controller中加入对应状态，确保状态名一致。
3. 动画若需要编辑，仍通过Blender MCP制作并保持in-place，再按现有流程接入。
4. 在现有输入或技能请求入口调用下面的方法；技能自己的冷却/解锁条件由技能模块管理。

示例（命名空间OCDesign.Samurai；在角色初始化之后调用）：

bool TrySkill(SamuraiCombatant actor, SamuraiActionDefinition skill, Vector3 direction)
{
    return actor.Actions != null
        && actor.Actions.TryStartAttack(skill, -1, direction);
}

-1表示独立攻击，不进入普通连击序号。当前高架势的SprintAttack和DodgeAttack是明确特例：有效下一次轻击均进入03100并将ComboIndex设0，随后沿当前链续03110→03120→03210。Profile.combo已为新四连，dodgeAttackToCombo1字段引用03100；旧同名ARPG回接资产留存但未用于当前高架势。中架势不混入该高架势回接链，其他独立招保持原规则。请求只在角色可行动状态接受，还会检查动作配置、Animator状态和耐力；返回false时不要先行扣除技能资源或播放成功特效。
当前高四段普攻、中六段普攻、强击链与蓄力释放由SamuraiActionController在合法窗口内部提交。需要新增跳跃、施法等全新状态时，在协调器中明确其时序/打断规则，再调用已有服务；不要从输入脚本直接改Animator状态来绕过战斗时序。
技能入口不应额外调用第二次Tick，否则会重复推进移动、恢复和时间。

五、接命中特效、音效或飘字

把表现写在独立MonoBehaviour中，订阅actor.DamageDealt。例如回调签名：

void OnDamage(ISamuraiDamageReceiver target, SamuraiHitResult result, Vector3 point)
{
    if (result == SamuraiHitResult.Hit || result == SamuraiHitResult.Killed)
        SpawnHitEffect(point);
}

SpawnHitEffect由自己的对象池/表现模块实现。格挡、完美格挡、闪避使用各自结果分支；几何接触不等于实际伤害，不能对所有事件统一播放流血。需要受击方音效可订阅HitReceived；命中点由DamageDealt提供。
刀光如需直接观察检测轨迹，可订阅actor.Weapon.SweepQueried；只作表现，不在回调里再次伤害目标。不要在绘制Gizmos时执行物理查询。

六、新增可破坏物或其他受击对象

在带有启用的非Trigger Collider的根对象上，实现ISamuraiDamageReceiver。Collider可以位于其子对象；所在Layer必须包含在攻击者Profile.hitMask中。每个受击根返回统一接口实例，多个子碰撞体仍按同一目标去重。

示例：

public sealed class BreakableTarget : MonoBehaviour, ISamuraiDamageReceiver
{
    [SerializeField] int team = 1;
    [SerializeField] float health = 50f;
    public Transform DamageRoot => transform;
    public int Team => team;
    public bool CanReceiveDamage => isActiveAndEnabled && health > 0f;

    public SamuraiHitResult ReceiveHit(SamuraiDamageHit hit)
    {
        if (!CanReceiveDamage || (hit.Source != null && hit.Source.Team == Team))
            return SamuraiHitResult.Ignored;
        health = Mathf.Max(0f, health - Mathf.Max(0f, hit.Damage));
        return health <= 0f ? SamuraiHitResult.Killed : SamuraiHitResult.Hit;
    }

    public void Stagger(float seconds) { }
}

此类需要using UnityEngine和using OCDesign.Samurai。示例不包含模型破碎/销毁，由自身表现和生命周期处理；非角色可选择忽略Stagger。需要格挡等完整规则的新角色可复用SamuraiDamageResolver与相关服务，或直接使用现有完整角色组件。
SamuraiTargetLock与训练AI当前仍以SamuraiCombatant为角色目标；自定义可破坏物已经能被武器命中，但要成为锁定或AI目标，仍需扩展相应目标选择规则。

七、单独复用武器几何查询

WeaponTrailDetector是完全独立于本战斗角色的几何查询器。创建自己的实例，实现IWeaponTrailFilter.IsTarget/IsEnvironment，提交WeaponTrailSweep中的上一帧/当前帧Base、Tip和Radius，然后调用Query(sweep, hitMask, obstructionMask, filter)。
Query返回IReadOnlyList<WeaponTrailContact>，包含Collider、世界接触点、该时刻刀根和归一化轨迹时间。结果使用查询器内部缓冲，只在下一次Query或QuerySector之前有效；不要长期保存该列表，也不要在遍历期间用同一实例递归查询。过滤器应只判断，不修改场景或重新发起检测。
几何层保留不同刀身轨迹上的接触，由上层完成视线检查和按受击目标去重。角色战斗直接使用SamuraiWeaponAttack即可获得现有有效窗口、阵营及伤害适配。

十三、独立受击后退（2026-10-21）

ActionDefinition.knockbackDistance/knockbackSeconds
  → SamuraiWeaponAttack提交SamuraiDamageHit.KnockbackDistance/KnockbackSeconds
  → SamuraiDamageResolver给出受击结果
  → SamuraiCombatant在Hit/GuardBroken/Killed时调用SamuraiKnockback.Apply
  → 正常Tick末尾推进SamuraiKnockback
  → SamuraiCharacterMotor.DisplacePlanar → CharacterController.Move

Knockback不持有动作状态机、伤害规则或输入，方向在命中时取目标远离来源的水平向量，原地重合时回退角色后向；曲线为开始较快、逐渐减速的距离积分。目标撞墙时不补移被挡住的距离；新命中替换旧后退，不无限叠加。距离0关闭，ResetCombat和OnDisable清空；IsBeingKnockedBack为只读观测。HitStop分支直接跳过正常Tick，因此后退与动作时间一起冻结，恢复后完成剩余时间。
普通格挡/闪避/完美格挡不会启动新后退；死亡命中也允许完成本次后退。暴击仅乘生命伤害，不乘后退或耐力伤害。自定义ISamuraiDamageReceiver可选择读取这两个伤害包字段并复用该服务；破坏物示例没有角色胶囊，可忽略后退。
